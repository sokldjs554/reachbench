# 직접 수행할 일과 면접 안내

## 기여 구분

**Codex가 수행:** 공고·공식 기술·도구 조사, 주제 선택, 실험 설계, Python 시뮬레이터·인식·경로 계획·평가·데모 구현, 자동 테스트, 결과 기록, 문서 작성과 배포 작업.

**사용자가 제공:** 지원할 공고, 기존 프로젝트의 성격, 보완하고 싶은 역량과 요구사항, GitHub 저장소 생성. 실제 개발·재실행·설계 변경·실물 실험을 수행했다는 증거는 아직 없다.

본인이 이해하거나 바꾼 부분이 생기면 아래 수행 기록을 직접 채울 것. 현재 저장소를 그대로 본인의 독자 개발 성과로 작성하지 않는다.

## 직접 재현할 순서

1. README 명령으로 환경 설치 후 pytest와 평가를 재실행한다. 결과 파일을 별도 디렉터리에 보관한다.
2. 데모에서 기본·어두운 조명·가림·보정 오차를 비교하고 같은 seed의 두 방법을 설명한다.
3. `pixel_to_world`, `ik`, `edge`, `plan`, `rollout`을 읽는다. 카메라 높이를 알면 왜 픽셀에서 평면 위치를 계산할 수 있는지 식을 유도한다.
4. 개선 방법의 no_path/goal_blocked 사례에서 오차, 안전 여유, 격자 간격의 영향을 살핀다. no_path는 실제 경로가 존재하지 않는다는 증명이 아니다.
5. 본인 변경 실험으로 안전 여유를 6/12/24 mm, 이미지 크기를 160/320/640으로 비교한다. 원 평가 seed로 조정한 뒤에는 새로운 seed 범위를 따로 평가한다.
6. 변경 diff, 설계 이유, 성공·실패 수, 시간 분포, 예상과 달랐던 점을 직접 기록한다. 그때부터 해당 변경만 자신의 기여로 설명한다.

## 90초 설명 골격

“이미지 분석 결과가 실제 움직임의 실패로 어떻게 이어지는지 확인하기 위해, AI 도구와 함께 카메라 기반 로봇팔 접근 시뮬레이션을 만들었습니다. 첫 RGB 이미지에서 색상 영역을 분리하고 카메라 보정값으로 평면 좌표를 추정한 다음, 역기구학과 A*로 관절 경로를 생성합니다. 시뮬레이터 정답은 평가에만 쓰며, 인식과 계획의 기여를 네 가지 조합으로 분리했습니다. 어두운 조명에서는 HSV가 검출 누락을 줄이지만, 가림은 해결하지 못합니다. 이후 별도 평가에서 기준점 기반 좌표 보정을 추가해 보정 오차를 개선했지만, 기준점 배치가 틀리면 여전히 실패했습니다. 현재는 기구학 접근 작업이고 실제 로봇·학습 모델·보행 제어는 검증하지 않았습니다. 제가 직접 검증·수정한 부분은 [직접 수행 후 사실만 기입]입니다.”

## 예상 질문

- **왜 학습 모델이 없나?** 작은 색상 고정 작업에서 인식→동작→평가 연결을 먼저 검증했다. 일반화를 주장할 수 없으며 실제 장면에는 학습 기반 검출·추적과 별도 데이터 검증이 필요하다.
- **정답을 몰래 쓰지 않았나?** perceive는 RGB와 보정값만 받는다. plan은 추정 목표·장애물과 알려진 로봇 기구학만 받는다. 실제 목표·Bullet 객체는 마지막 평가에서 쓴다. 단, 카메라와 물체 높이를 알고 있다는 강한 가정은 공개한다.
- **이것이 로봇 제어인가?** 관절 궤적 생성 및 기구학 실행 검증이다. 모터 토크 제어, 관절 추종 오차, 동역학 안정성은 다루지 않았다. 이를 실물 제어 성능이라고 부르면 안 된다.
- **왜 성공률이 낮은 조건을 넣었나?** 가림·보정 실패를 의도적으로 포함했다. 전체 비율은 설계된 조건 혼합에 대한 것이며 현장 분포를 대표하지 않는다.
- **단순 RGB 기준 방법이 약하지 않나?** 맞다. 현업 SOTA 비교가 아니라 인식과 계획의 인과를 구분하기 위한 교육적 기준이다. HSV+직접 접근, RGB+A* 절제 실험을 함께 제공한다.
- **안전한가?** 실제 장비 안전 시스템이 아니다. 제한된 정적 장면의 이산 충돌 검사와 경로 여유 거리만 확인했다.
- **학습 데이터를 만들었나?** 합성 이미지·정답·조건·관절 궤적을 수집하고 무결성을 점검했다. 정책 학습에 투입하거나 학습 증강의 효과를 측정하지 않았다.

## 장비·연산 확장

- CPU만으로: 핸드아이/카메라 보정 오차 추정, 동적 장애물·재관측, 다른 색상·배경, 연속 충돌 검사, ROS2 메시지·rosbag 연계, MuJoCo/PyBullet 실제 모터 제어기.
- 카메라와 저가 로봇팔: 좌표계 검증, 관절 한계·엔코더·모터 지연, 실제 조명·색상 변화, 물리 비상정지 및 운영 절차, sim-to-real 오차 분해.
- GPU/학습 데이터: 범용 검출·포즈 추정, 시연 데이터 정책 학습과 held-out 평가, 데이터 증강 전후 비교. 단순히 모델을 붙였다는 사실보다 실패 분포가 어떻게 바뀌는지 측정할 것.
- 휴머노이드 플랫폼: 3D 자세·접촉·균형과 Whole-body Control, 보행을 별도 실험으로 검증. 이 프로젝트의 성공률을 이전하지 않는다.

## 이번 보완에서 직접 참여할 작업

아래는 제안이며 사용자가 이미 수행한 기여가 아니다.

1. `PYTHONPATH=. python scripts/reproduce_v2.py`를 직접 실행하고 기록이 일치하는지 확인한다. 환경·명령·로그를 본인 수행 표에 남긴다.
2. `estimate_translation`과 `reference_observations`를 읽고 목표 정답을 받지 않으면서 왜 편향을 추정할 수 있는지 설명한다. 등록 기준점 좌표는 알려져 있다는 가정을 명시한다.
3. 별도 브랜치에서 MIN_MARKERS/잔차 임계값을 바꾸고 개발 seed로 결정한다. 아직 쓰지 않은 seed 4000–4019에 평가해 이동 보류율·성공·충돌·오차를 비교한다.
4. 기준점을 함께 옮겼을 때 잔차가 작아도 틀리는 이유를 직접 수식으로 유도한다. 기준점 하나의 잘못된 대응과 전체 기준점 오배치가 다른 실패임을 설명한다.
5. 새로운 음수 X/Y 편향 또는 회전 편향을 추가한다. 평행이동 보정의 적용 범위를 검증하고, 회전까지 추정하는 방법을 구현한다면 새 개발/평가 split을 정한다.
6. 본인이 바꾼 코드 diff, 사전 실험 설정, 실패를 포함한 전체 결과와 예상과 달랐던 점을 기록한다. 그 부분부터 본인 기여로 소개한다.

면접에서는 **기존 59%와 새 100%는 다른 평가 집합**이라는 점, +65 mm paired 조건의 0/20→20/20과 두 스트레스의 0/20을 함께 말한다. 정상 기준점 100/100을 로봇 일반 성공률로 설명하지 않는다. 새 목표 가림 복구, 파지, ROS 2, 모터 제어를 구현했다고 말하지 않는다.
