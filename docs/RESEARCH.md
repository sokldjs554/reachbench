# 공고 조사와 방향 선정

조사일: 2026-11-17 (Asia/Seoul). 공개 웹 원문을 읽고 정리했다. 채용 상태·전형 일정은 지원 시 다시 확인할 것.

## 1. 공고에서 확인한 사실

[원티드 381292](https://www.wanted.co.kr/wd/381292)의 주요업무:

- 로봇의 인식·판단·행동을 위한 Physical AI 기술 연구 및 구현
- 시뮬레이션 환경 구축 및 가상 데이터 기반 실험
- 카메라, 거리, 힘, 촉각 등 센서를 활용한 로봇 상태·위치 인식
- 공간·자세·동작 추정과 2족 보행 / Whole-body Control 등 제어 연계
- 로봇 학습 데이터 수집, 전처리, 정제, 증강 파이프라인
- 실제 환경 및 실증 프로젝트 적용과 성능 검증

자격요건: 관련 전공, 학사·석사 졸업 또는 졸업 예정, Python 또는 C/C++ 개발 경험, 로봇·AI·제어·컴퓨터 비전 중 한 분야 이상에 관심, 직접 학습·구현하는 태도. 정규직 전환형 3개월 인턴.

[회사 공식 동일 직무](https://tommoro.ai/en/career/%EC%9D%B8%ED%84%B4-physical-ai-robotics-sw-r-d)에서도 동일한 업무와 자격요건을 확인했다. 공식 페이지의 **추가 우대사항**은 ROS/ROS2, PyTorch/OpenCV, 로봇 시뮬레이터·3D 환경, 센서 활용, 제어·컴퓨터 비전·강화학습·모방학습 프로젝트 경험이다. 이 추가 항목을 원티드 원문에 있었다고 인용하지 않는다. 지원자의 전공·졸업 상태는 제공되지 않아 자격 충족 여부를 판단하지 않았다.

## 2. 회사 기술과 연결

[회사 공식 소개](https://tommoro.ai/)의 HABILIS 구성은 Agent(작업 계획·도구·로봇 연결), Brain(시연 데이터 기반 조작 스킬), Console(데이터·학습·추론·배포·운영), Data Foundry(현장·Human·Teleoperation 데이터)이다. [About](https://tommoro.ai/en/about)는 VLA 기반 로봇 파운데이션 모델, 모방·강화학습, 실시간 제어·추론, 실행 경험을 평가·학습으로 연결하는 흐름을 설명한다. 이는 회사가 공개적으로 설명한 기술 방향이며 독립적인 성능 검증이 아니다.

ReachBench는 카메라→공간 추정→경로→기록→실패 분석을 작은 단위로 재현한다. 회사의 모델이나 제품을 구현했다는 주장은 하지 않는다. 특히 본 프로젝트의 고정 색상 분할은 학습된 Physical AI/RFM/VLA가 아니다.

## 3. 대안 비교와 선정 근거

점수는 설계 판단(5점 만점)이며 실험 성능 수치가 아니다.

| 후보 | 공고 연관성 | CPU 실행 가능성 | 평가 명확성 | 데모 전달력 | 판단 |
|---|---:|---:|---:|---:|---|
| 휴머노이드 RL 보행 | 5 | 1 | 3 | 5 | 학습 예산·접촉 제어 검증 부족 |
| VLA 기반 파지 | 5 | 2 | 3 | 5 | 모델·데이터·GPU 의존과 파지 검증 비용 |
| 실내 시각 내비게이션 | 4 | 4 | 4 | 4 | SLAM·지도·위치추정까지 범위가 커짐 |
| **카메라 기반 2관절 접근** | **4** | **5** | **5** | **4** | 작은 작업에서 인식 오차가 동작 실패로 이어지는 관계를 분리 평가 가능 |

선정 문제: 고정 RGB 카메라로 붉은 작업물과 푸른 장애물을 인식하고, 2관절 평면 로봇팔 끝점을 작업물 XY 좌표의 35 mm 이내로 접근시킨다. 링크 전체가 장애물에 부딪히면 실패. 수직 도달·파지·이송은 범위 밖이다.

## 4. 기술 선택과 디자인 조사

- [PyBullet](https://pybullet.org/wordpress/): GUI/GPU 없이 DIRECT와 CPU TinyRenderer 사용. 도형 생성·관절 기록·독립 충돌 쿼리에 적합. 이번 구현은 상태를 직접 설정하므로 동역학 제어 시뮬레이션으로 소개하지 않는다.
- [OpenCV HSV inRange](https://docs.opencv.org/4.x/da/d97/tutorial_threshold_inRange.html): 밝기가 변할 때 고정 RGB 임계값과의 차이를 설명하고 비교할 수 있다. 범용 객체 인식 대체물이 아니다.
- [Foxglove 3D panel](https://docs.foxglove.dev/docs/visualization/panels/3d): 이미지, 프레임, 경로, 시간 동기화·비교 기능을 조사했다. 이를 참고해 초기 이미지와 관절 기록 재생을 연결했다.
- [Rerun](https://rerun.io/): 다중 모달 데이터를 기록·변환·탐색하고 실패를 원본 데이터로 추적하는 구조를 참고했다.
- [HABILIS Console](https://tommoro.ai/console): 로봇 제어·수집·학습·배포를 묶는 흐름을 확인했다. 로그인 이후 제품 UI를 직접 사용한 것은 아니다.

외부 제품의 이미지·브랜드·UI 코드·상용 자산을 가져오지 않았다. 짙은 공간 뷰, 중립색 작업 패널, 시간축, 입력·인식·행동 단계, 근거 JSON 다운로드를 적용했다.

## 5. 기존 프로젝트와의 관계

사용자가 설명한 범위에서 Pathology Edge Lab은 이미지 분석·모델 검증, Harbinger는 데이터 분석을 보여준다. 해당 저장소나 성과를 이번에 검토하지 않았으므로 세부 기여나 성능은 추정하지 않는다. ReachBench의 추가 가치는 좌표 변환·역기구학·충돌 회피·시뮬레이션 기록이라는 연결이다. 직접 실물 하드웨어를 다루거나 학습 정책을 훈련한 경험을 대체하지 않는다.
