# v3 실험 조건·결과·실패

2026-11-17 KST, Codex가 실제 실행. Python 3.11.18 / MuJoCo 4.0.1 / Linux x86-64 / CPU 물리, EGL 렌더링. 실물 로봇·학습 모델 실험이 아니다.

## 고정한 비교

- 개발: seed 10–14 × 4조건 × 2방법 = 40회. `dev-final`에서 기준 5/20, 개선 15/20. 개발 과정에서 외력 지속 시간을 120 ms에서 60 ms로 줄였다. 최종 평가를 시작하기 전에 제어 파라미터를 확정했다.
- 최종: seed 100–119 × 4조건 × 2방법 = 160회. 같은 seed/조건의 초기 물체 위치와 가림판/외력 설정이 동일하다.
- 기준 `one_shot`: 정면 RGB-D 한 번 → IK·접근 → 집기·놓기. 미검출이면 중단, 빈 집기면 실패.
- 개선 `feedback`: 정면 미검출 시 후면 카메라; 접근 후 후면 재관측으로 위치 갱신; 빈 집기 판정 시 최대 한 번 손을 열고 다시 관측·집기.
- 재관측과 재시도를 함께 바꿨다. 여기 제시한 160회는 두 기능을 합친 비교다. 재관측을 고정하고 재시도만 바꾼 [후속 실험 42회](retry-study/README.md)를 별도로 공개했다.

두 고정 카메라는 224×224 RGB-D, fovy 45°. 색상 마스크·형태학 처리·최대 연결 성분(12픽셀 이상)·depth 역투영·표면 경계 중심을 사용한다. 추정 z는 알려진 테이블/큐브 높이에서 .382 m로 설정한다. 매 프레임의 임의 물체 6D pose를 추론하는 모델이 아니다.

물리 dt=2 ms, Panda 7개 관절 모터 + 평행 그리퍼. IK는 별도 계산용 state에서 감쇠 최소제곱을 풀며 실제 실행은 ctrl→mj_step이다. 웨이포인트는 접근·하강·상승·트레이·후퇴 순서로 고정한다. **일반 장애물 회피 경로 계획은 아니다.** 로봇과 가림판 접촉을 평가하지만 범용 자기 충돌/안전 제어를 검증한 것은 아니다.

## 조건

- 기본: 테이블 위 무작위 XY, 장애 가림 없음.
- 목표 가림: 물리 가림판(.30×.036×.22 m)이 정면 시야를 차단. 후면 시야는 확보되는 제한된 설계다. 두 시야 모두 가린 조건까지 일반화하지 않는다.
- 위치 변화: 첫 관측 후 물체에 +Y 방향 2 N을 60 ms 가하고 350 ms 안정화. 정답 좌표를 제어기에 알려주지 않는다.
- 범위 밖: x=.95 m에 배치. 테이블 경계를 벗어나 시작 안정화 중 바닥에 놓이므로 시야/범위/높이 변화가 함께 발생하는 실패 조건이다. 순수 도달 거리만의 실험으로 해석하지 않는다.

## 지표 정의

- 성공: 물체 중심이 트레이 중심 (.48,.24 m)에서 |dx|<65 mm, |dy|<60 mm, .37<z<.42 m; 손가락 간격>65 mm, 로봇/가림판 접촉 없음. 최종 상태 판정이며 장시간 안정성 보장은 아니다.
- 놓기 오차: **최종 물체 중심 ↔ 트레이 중심의 XY 거리**. 이동하지 않아도 계산한다. 손끝 오차·인식 오차가 아니다.
- 인식 오차: 검출된 관측에서 추정 XY ↔ 평가용 물체 정답 XY. 각 실행의 관측 평균을 다시 실행 간 평균. 미검출은 제외하며 0으로 처리하지 않는다.
- lift_height_m: 시작 안정화 후 실제 물체 높이에 대한 최대 상승량.
- 충돌: 로봇과 가림판 접촉이 있었던 실행 수. 접촉 발생 시 첫 위치·시간을 기록한다. 이 데이터에서는 0회이므로 가짜 충돌 표시를 만들지 않는다.
- 처리 시간: 렌더러 생성·RGB-D·인식·IK·물리 실행의 CPU 벽시계 시간. 3개 병렬 worker와 다른 검증 작업의 CPU 경합을 포함한다. 실기 센서 지연·실시간 제어 주기와 다르다.

## 실패와 재시도

- 가림 기준: 20/20 목표 미검출, 이동 없음. 인식 오차 null, 놓기 오차는 시작 물체와 트레이 사이 거리.
- 위치 변화 기준: 20/20 빈 집기. 이전 관측 위치가 물체 이동 후 유효하지 않다.
- 개선 범위 밖: 18회 workspace gate, 2회 두 카메라 모두 목표 미검출. 모두 이동 없음.
- `shifted-107-feedback`: 첫 집기에서 손가락 간격이 닫혀 빈 집기로 판단, 한 번 재시도 후 성공. 실제 관측·모터·관절 기록을 공개했다. 손가락 간격이 넓다고 해서 항상 대상 큐브를 잡았다는 뜻은 아니므로 최종 배치 판정과 별도로 사용한다.

## 데이터·재현

[설정/코드 해시](../../dist/bench/config.json), [160회 전체](../../dist/bench/episodes.json), [집계](../../dist/bench/summary.json). `runs/`는 seed 100/101의 16회 및 실제 재시도 seed 107의 1회를 포함한다. 성공과 실패를 모두 저장하며 160회 전체로 성공률을 계산한다. 표시 예시를 골라 성공률을 계산하지 않는다.

NPZ: `rgb`, `depth`(m), `rotation`, `position`, `fovy`. JSON의 `sensors`에는 t, 카메라, 픽셀 검출·추정, 평가 정답과 오차가 있다. `trace`는 약 25 Hz의 qpos(7 arm + 2 finger + free cube), ctrl(7 arm command + 0–255 grip), phase, 시뮬레이션 t. 초기/최종 상태도 저장한다. 센서 관측은 행동의 특정 시점에서만 수집된다. JPEG는 확인용이며 무손실 RGB 원본은 NPZ에 있다.

```bash
python -m manipulation.evaluate --split dev --out work/dev --workers 3
python -m manipulation.evaluate --split eval --out work/eval --workers 3
python -m manipulation.controller --seed 107 --condition shifted --method feedback --out work/retry
```

제어 로직을 최종 평가 결과에 맞춰 다시 튜닝하지 않았다. 기록 누락(이동 없는 사례의 trace), raw RGB-D/action 저장, 높이 지표와 최종 replay 상태를 고친 뒤 평가를 재실행했다. 이 수정은 정책 동작·성공 판정을 바꾸지 않았다. 동작 결과는 같았고 벽시계 시간은 달라졌다. 개발 기록은 별도 보존한다.

## 웹 결과와의 경계

첫 화면은 실제 WASM MuJoCo 물리다. 브라우저는 Three.js의 RGB/depth, Python은 MuJoCo EGL 렌더러를 사용한다. 픽셀·IK 부동소수점·단계 분할 차이 때문에 결과나 끝점이 완전히 같지 않다. Python 75%를 웹 모든 seed의 성공률로 대체하지 않는다. 검증한 브라우저 조건은 [VALIDATION.md](VALIDATION.md)에 명시했다.

기록 모드의 3D는 해당 실행의 qpos를 **재구성**한다. 실제 원본 카메라 JPG/NPZ는 해당 실행에 속하며 t를 표시한다. 관측 카드들은 전체 실행 이력이므로 시간 탐색 시 매 순간의 카메라 영상이라고 해석하지 않는다. 기존 PyBullet 실제 렌더 프레임과 동기화된 2D 경로는 [이전 실험](https://reachbench-vision-control.ykh13571.chatgpt.site/legacy/)에서 유지한다.
